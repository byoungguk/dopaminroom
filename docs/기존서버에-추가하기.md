# 기존 서버(강남호빠)에 도파민 사이트 추가하기

이미 돌고 있는 `blog20260819`(강남호빠) 서버에 도파민 사이트를 함께 올리는 방법.
nginx 는 **한 대만** 쓰고, 도메인으로 두 사이트를 나눠 서빙한다.

```
                    ┌─ 강남호빠.한국      → ~/blog/site/public
서버 nginx (80/443) ┤
                    └─ dopaminroom.kr     → ~/dopaminroom/dist
                         /admin/          → dopamin-admin 컨테이너
```

## 1. 공유 네트워크 만들기 (최초 1회)

두 compose 프로젝트의 컨테이너가 서로를 찾을 수 있게 한다.

```bash
docker network create web
```

## 2. 도파민 코드 받기

**디렉터리 이름이 `dopaminroom` 이어야 한다.** 기존 서버의 compose 가
`../dopaminroom/dist` 를 마운트하기 때문이다.

```bash
cd ~
git clone https://github.com/byoungguk/dopaminroom.git dopaminroom
cd dopaminroom
cp .env.example .env
nano .env
```

`.env` 에서 바꿀 값:

| 항목 | 값 |
|---|---|
| `BASE_URL` | 인증서 발급 전에는 `http://dopaminroom.kr/`, 발급 후 `https://dopaminroom.kr/` |
| `ADMIN_USER` | 고객에게 줄 아이디 |
| `ADMIN_PASSWORD` | 고객에게 줄 비밀번호 |
| `ADMIN_SECRET_KEY` | `openssl rand -hex 32` 결과값 |

`HTTP_PORT` / `HTTPS_PORT` 는 이 구성에서 쓰지 않는다. (nginx 를 띄우지 않음)

## 3. 빌드 + 관리자 컨테이너 기동

```bash
cd ~/dopaminroom
./scripts/build.sh                      # dist/ 생성
docker compose up -d --build admin      # 관리자만 기동 (nginx 는 띄우지 않는다)
docker ps | grep dopamin-admin
```

## 4. 기존 서버 쪽 설정 반영

`blog20260819` 저장소에 아래 변경이 이미 들어가 있다.

- `docker-compose.yml`: `../dopaminroom/dist` 마운트, nginx 를 `web` 네트워크에 연결
- `nginx/conf.d/dopaminroom.conf`: 80 포트 서버 블록
- `nginx/conf.d/dopaminroom-ssl.conf.disabled`: 443 템플릿 (인증서 발급 후 활성화)

이 프로젝트는 git 이 아니라 파일 전송으로 배포하므로, 바뀐 3개 파일을 올린다.
(로컬 PC 에서 실행)

```bash
cd /c/Users/jjang/projects/blog20260819
tar czf - docker-compose.yml nginx/conf.d/dopaminroom.conf nginx/conf.d/dopaminroom-ssl.conf.disabled \
  | ssh -i blog-key.pem ubuntu@<서버IP> 'tar xzf - -C ~/blog'
```

그 다음 서버에서 반영한다.

```bash
cd ~/blog          # 강남호빠 프로젝트 경로
docker compose up -d nginx
docker compose exec -T nginx nginx -t      # 설정 검증 (반드시 ok 확인)
docker compose exec -T nginx nginx -s reload
```

> `nginx -t` 가 실패하면 되돌린다: `rm nginx/conf.d/dopaminroom*.conf` 후 reload.
> 기존 강남호빠 사이트가 끊기지 않게 검증 전에는 reload 하지 않는다.

## 5. DNS 연결

메일플러그에서 `dopaminroom.kr` 의 A 레코드를 **이 서버 IP** 로 바꾼다.
(기존 GitHub Pages 용 185.199.x.x 4개는 삭제)

| 타입 | 호스트 | 값 |
|---|---|---|
| A | @ | 서버 IP |
| CNAME | www | dopaminroom.kr |

## 6. https 발급

DNS 가 반영된 뒤 실행한다. 인증서는 기존 프로젝트의 certbot 이 발급·갱신한다.

```bash
cd ~/dopaminroom
./scripts/init-cert-shared.sh --dry-run   # 먼저 검증
./scripts/init-cert-shared.sh             # 실제 발급
```

발급 후 `.env` 의 `BASE_URL` 을 `https://dopaminroom.kr/` 로 바꾸고 다시 빌드한다.

```bash
nano .env
./scripts/build.sh
```

> 기존 프로젝트 경로가 `~/blog` 가 아니면 `BLOG_DIR=/실제/경로 ./scripts/init-cert-shared.sh` 로 실행한다.

## 7. 자동 반영 등록

관리자 페이지에서 저장하면 `.admin/rebuild.request` 가 생긴다.
이를 감시해 다시 빌드하는 스크립트를 상주시킨다.

```bash
sudo tee /etc/systemd/system/dopamin-watch.service > /dev/null <<EOF
[Unit]
Description=dopaminroom rebuild watcher
After=docker.service

[Service]
Type=simple
User=$USER
WorkingDirectory=$HOME/dopaminroom
ExecStart=$HOME/dopaminroom/scripts/watch-changes.sh
Restart=always

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now dopamin-watch
sudo systemctl status dopamin-watch
```

## 8. 확인

| 주소 | 내용 |
|---|---|
| `https://dopaminroom.kr` | 도파민 사이트 |
| `https://dopaminroom.kr/admin/` | 관리자 페이지 |
| 강남호빠 도메인 | 기존 사이트가 그대로 동작하는지 함께 확인 |

## 점검 명령

```bash
docker ps                                   # 두 사이트 컨테이너 상태
cd ~/blog && docker compose logs -f nginx   # 접속 로그
docker logs -f dopamin-admin                # 관리자 로그
journalctl -u dopamin-watch -f              # 자동 반영 로그
cat ~/dopaminroom/.admin/last-build.txt     # 최근 반영 시각
```

## 되돌리기

도파민 사이트만 내리려면:

```bash
cd ~/dopaminroom && docker compose down
cd ~/blog && rm nginx/conf.d/dopaminroom*.conf
docker compose exec -T nginx nginx -s reload
```
